# Offline request estimation

`cl100k_base` and `o200k_base` come from OpenAI's MIT-licensed [tiktoken](https://github.com/openai/tiktoken) project. The source rank files are [cl100k_base](https://openaipublic.blob.core.windows.net/encodings/cl100k_base.tiktoken) and [o200k_base](https://openaipublic.blob.core.windows.net/encodings/o200k_base.tiktoken). `generate.py` pins their SHA-256 hashes and deterministically compresses local downloads. The bundled license is `internal/openaitokenizer/LICENSE`. No runtime downloads, Python, native extensions, or provider requests occur.

Run `python3 scripts/openai-tokenizer/generate.py /path/to/downloads` to regenerate. Reference fixtures use Python `tiktoken==0.12.0`, `encode_ordinary`, and the same hash-verified ranks. They cover ten writing/content categories, whitespace, contractions, tool-like JSON, and special-token-looking ordinary text. The shared counter splits spans longer than 512 runes to bound BPE work; such segmentation can differ from exact full-span tokenization.

The explicit model mapping follows tiktoken's published `model.py`. Recognized OpenAI models and qualified OpenRouter OpenAI IDs use the corresponding vocabulary plus 10% text headroom. Unknown aliases, unverified future models, and other providers use the larger of cl100k and o200k text counts plus 25% headroom. This proxy is an uncertainty allowance, not a mathematical upper bound for arbitrary tokenizers. It must never be described as that model's official tokenizer. The DeepSeek V4 gateway retains its own verified tokenizer and image contract.

`provider.EstimateRenderedRequest` covers Chat Completions, Responses and Anthropic Messages input. It excludes transport controls, counts system/history/tools/output schemas, preserves literal tool arguments, and separates actual media parts. It does not fetch remote URLs. Known OpenAI image families follow the [official patch/tile budgets](https://developers.openai.com/api/docs/guides/images-vision); patch rounding uses a conservative ceiling. Other images use a pixel proxy, or 32,768 tokens when dimensions cannot be read locally. Opaque documents retain at least their encoded-byte budget and 4,096 tokens; page expansion cannot be inferred exactly. Official [Responses input counting](https://developers.openai.com/api/reference/resources/responses/subresources/input_tokens/methods/count) can be used by a transport that explicitly owns that network operation, but is not silently added to request preparation.

`RequestFormatJSON` is for complete model input from opaque custom transports. It counts every supplied field with the proxy estimator, reports `generic_payload_estimate`, and does not claim visibility into the final server rendering. Hosts must omit their own routing, credentials, and runtime metadata from this input. Native usage and compatible canonical-prefix deltas remain the pressure authority; unknown media/model behavior can still overflow, and existing provider-overflow recovery remains required. Estimator source versions invalidate prior incompatible calibration.
